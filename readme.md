# Docker
- It is a way to package and run applications in an environment that is seperate from the host.
- It lets the application to be run on anything with docker.
- Kind of like a packager that has a server close to git.

- PID1
    The first process started during the system boot.
    All other processes are started by PID1.
    It manages all other porcesses inside in the container.

- CMD
    The instruction specifies the default command to run when a container is started from the docker image. If no command the default is used.

- ENTRYPOINT
    Sets the default executable for the container
    Use it when a base command is always needed to run. for example always the same args

## Objects
- Images
    Basicly the namespace that you want the project/application to have.
    It is the read-only template that instructs how to create the docker container.

- Containers
    A runable instance of the image.
    It is quite isolated from other containers and host machines and networks.
    Virtual machines virtualize an entire machine down to hardware layers whereas containers only virtualize software layers above the operating systems

## Virtual Machines vs Docker

- VM
    - It is a direct duplicate of a whole system.
    - has its own kernel
    - shares hardware
    - Big since it is a whole computer os.
    - different os is okay

- Docker
    - A container that has everything needed for a system to run an application.
    - No kernel, still the process of the host.
    - Namespaces are changed from the host kernel so that it works
    - run on host machine
    - starts a procsses not a whole os so faster.
    - smaller size
    - container matches the kernal


## Secrets vs Environmental variables

- Secrets
    - During compose a file or files that becomes read-only.
    - Only read if needed by entrypoints with cat.
    - Cannot be found with docker inspect. Child proccesses dont inherit it.
    - The docker container does not have the secrets so cannot leak it.
    - It keeps the secrets seperate from code and the images.

- Environmental variables
    - NAME=VALUE pair that all proccesses have.
    - .env sets up environmental variables for the docker containers. IE kind of like setting up a namespace variables.
    - visible in docker inspect
    - the whole container has them.
    - non sensitive things

## Docker Network vs Host Network

- Docker
    - A bridge network
    - A virtual switch, only exists in the software.
    - Each container is connected via a virtual cord.
    - A private subnet
    - Built-in DNS, A small DNS server per container.
    - Isolated by default.

- Host Network
    - When network_mode is set as host it is not a private network. It runs on the host machines network.
    - No isolation
    - Port conflicts, two containers cannot have the same port
    - No service-name DNS, containers find each other via local host.
    - Faster.

## Docker Volumes vs Bind Mounts
both are ways to keep and share data between docker containers.


- Docker Volumes
    - Storage that docker creates and manages
    - Easier to manage across docker environments
    - For storing data that is generated by containers

- Bind Mounts
    - Takes a specific folder on the host and makes it a path inside the container.
    - Paths for sharing info. A PATHWAY between the docker containers and host.
    - Direct acess to files on host files
    - Changes made on the host file reflects onto the docker containers
